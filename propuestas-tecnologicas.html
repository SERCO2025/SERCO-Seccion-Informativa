01 · Audio / ingeniería de software
DISTRHO.
PLUGIN FRAMEWORK

Un framework C++ para desarrollar plugins de audio con una base de código común y exportarlos a varios formatos de plugin. DPF es la herramienta de construcción; el producto comercial sería el plugin que creemos.

C++ · DSP · VST3 / CLAP / LV2

Diseñar sonido. Construir herramientas. Vender soluciones.

DPF no es un DAW ni un editor de audio: es una infraestructura de desarrollo que nos permite crear instrumentos y procesadores de audio con interfaz gráfica y procesamiento DSP.

Licencia principal: ISC

DISTRHO Plugin Framework (DPF) es un framework ligero en C++ que simplifica la creación de plugins de audio. Proporciona una API para el procesamiento de audio y la interfaz gráfica, y permite exportar el mismo proyecto a diferentes formatos compatibles.

Procesamiento DSP

El código que modifica o genera audio: filtros, ganancia, dinámica, modulación, análisis, generación de tonos y otros algoritmos.

Interfaz de usuario

Controles, medidores, perillas, interruptores, selectores y comunicación entre interfaz y motor de audio.

Integración con anfitriones

El plugin se carga dentro de un programa anfitrión compatible. El anfitrión administra pistas, audio, automatización y sesiones.

Estado y parámetros

DPF incluye mecanismos para comunicar parámetros entre UI y DSP y guardar/restaurar estado según las capacidades del formato.

Formatos mencionados por el proyecto

VST3CLAPLV2VST2LADSPADSSIJACK / Standalone

La disponibilidad concreta de cada formato y función debe revisarse en el archivo FEATURES del repositorio y en la versión que se compile. No todos los formatos tienen el mismo estado de mantenimiento ni las mismas condiciones legales.

Herramientas iniciales

  • Control de ganancia / trim de entrada y salida.
  • Inversión de polaridad.
  • Conversión mono, balance y control de canales.
  • Medidores RMS, pico y reducción de ganancia.
  • Control de anchura estéreo y utilidad M/S.
  • Filtro pasa-altas y pasa-bajas.
  • Generador de tono y medidor de frecuencia.

Productos de mayor complejidad

  • Ecualizadores paramétricos y shelving.
  • Compresores, limitadores, expansores y gates.
  • De-esser y control de sibilancia.
  • Puertas de ruido y restauración ligera.
  • Reverb, delay, chorus, phaser y saturación.
  • Analizadores de espectro y correlación.
  • Herramientas de voz para podcast, streaming y locución.
Secuencia sensata: comenzar con 2–3 utilidades pequeñas, validar estabilidad y calidad sonora, documentar presets y compatibilidad; después construir una suite coherente. Un compresor o ecualizador no debe salir al mercado sin pruebas auditivas, mediciones y validación con distintos anfitriones.
Venta individual

Plugins de utilidad con precio accesible, versiones gratuitas limitadas y versión Pro con funciones avanzadas.

Paquetes por actividad

Bundle de voz, podcast, streaming, edición, mezcla y masterización básica.

Licencia comercial

Licencias para estudios, escuelas, emisoras, productoras y equipos de trabajo.

Personalización

Desarrollo de plugins con marca, controles y flujo de trabajo específico para un cliente.

Contenido y formación

Presets, manuales, tutoriales, cursos y paquetes de configuración.

Soporte

Instalación, actualización, diagnóstico, compatibilidad y mantenimiento anual opcional.

Producto inicial recomendado

Una pequeña suite de utilidades para voz: ganancia, polaridad, mono/estéreo, medidor de nivel y filtro de graves. Es un alcance más controlable que comenzar con un sintetizador complejo. La diferenciación comercial debe venir de la calidad, facilidad de uso, documentación en español, presets útiles y soporte real.

No prometer: compatibilidad universal, latencia cero, mejora sonora subjetiva ni funcionamiento en cualquier DAW. Publicar una matriz de anfitriones y sistemas probados.
  • Repositorio oficial DPF, Git y sus submódulos.
  • Compilador C++ compatible, CMake o Make según el flujo elegido.
  • Entorno de compilación de Windows (por ejemplo, MSYS2/MinGW o Visual Studio según configuración y compatibilidad de la versión).
  • SDK o encabezados necesarios para cada formato seleccionado.
  • DAW/anfitrión para probar carga, parámetros, automatización, guardado y audio.
  • Herramientas de validación de plugins, pruebas de CPU, memoria y audio.
DPF proporciona ejemplos dentro del repositorio. Conviene compilar primero un ejemplo sin modificar, verificar dependencias y después iniciar el primer plugin propio.

Flujo técnico

Clonar el repositorio
Obtener DPF desde GitHub y descargar sus submódulos de acuerdo con las instrucciones del proyecto.
Preparar compilador y dependencias
Instalar toolchain, CMake/Make y bibliotecas requeridas por la versión elegida.
Compilar un ejemplo
Verificar que el plugin de demostración se genera y carga en un anfitrión compatible.
Crear el DSP
Implementar algoritmo, parámetros, rangos, comportamiento en tiempo real y manejo de estados.
Diseñar interfaz
Crear controles legibles, escalables y accesibles; probar distintos tamaños de ventana.
Validar y empaquetar
Probar anfitriones, arquitecturas, automatización, instalación, desinstalación y firma/entrega.

Para Android existe un ecosistema diferente: AAP (Audio Plugins For Android). No se debe confundir un VST3 de Windows con un plugin Android. La adaptación requiere estudiar el soporte AAP y sus anfitriones; el proyecto AAP advierte que ciertas partes de su API pueden cambiar.

DPF declara licencia ISC para el framework, pero su documentación separa las condiciones de cada formato. Según su archivo LICENSING: LV2 y VST3 se indican como ISC; CLAP como MIT; VST2 como BSD-3; AU como ISC; JACK/Standalone incluye componentes MIT. LADSPA y DSSI utilizan encabezados LGPL-2.1+ y el propio proyecto advierte que la situación de uso comercial puede ser menos clara.

Para un producto comercial inicial, concentrarnos en CLAP, VST3 y/o LV2 después de verificar anfitriones, plataformas y avisos de atribución. Evitar LADSPA/DSSI en el primer lanzamiento salvo revisión legal específica.

Podemos conservar los derechos sobre el DSP, diseño de interfaz, marca, manuales y código original que escribamos, respetando la licencia de DPF y de cada dependencia. No atribuirnos la autoría del framework ni de sus componentes.

02 · Gestión documental / OCR
DOCUMENT CONTROL · OCR · SEARCH

Paperless-ngx

Un archivo digital organizado que permite recibir documentos, extraer texto mediante OCR, clasificarlos y recuperarlos por búsqueda. Especialmente útil cuando una oficina maneja expedientes, contratos, identificaciones, facturas y correspondencia.

Licencia: GPL-3.0

Del papel a la información localizable.

Paperless-ngx es un gestor documental autohospedado. No es solamente un escáner: el OCR convierte imágenes de documentos en texto indexable y la plataforma organiza metadatos, etiquetas, tipos, remitentes y permisos.

Servidor · API REST · OCR

Entrada de documentos

Importación de PDF, imágenes y otros formatos admitidos; consumo desde carpetas vigiladas, carga web y envío mediante API.

OCR y extracción

Reconocimiento de texto en documentos escaneados para permitir búsquedas dentro del contenido, con idiomas configurables.

Clasificación

Tipos documentales, etiquetas, corresponsales, rutas de almacenamiento, fechas y campos personalizados.

Búsqueda y recuperación

Localización por texto, título, filtros y metadatos; vistas guardadas y acceso desde navegador.

Control de acceso

Usuarios, grupos y permisos a nivel de objetos documentales; requiere diseño y pruebas de seguridad.

Historial y versiones

Administración de documentos y versiones, según la funcionalidad disponible en la versión instalada.

El sistema está diseñado para centralizar documentos de trabajo, pero no reemplaza por sí mismo una política legal de conservación, expediente, firma electrónica, cadena de custodia ni un sistema de gestión de casos jurídicos.

Oficina de traducciones

  • Guardar originales, escaneos, traducciones entregadas y comprobantes.
  • Clasificar por cliente, idioma, tipo de documento y fecha.
  • Localizar rápidamente nombres, números de referencia y texto extraído.
  • Vincular versiones del documento y conservar fuente recibida.
  • Crear un flujo de revisión y entrega con control de permisos.

Despacho jurídico / gestoría

  • Expedientes por cliente y asunto, con etiquetas y metadatos.
  • Digitalizar contratos, notificaciones, escritos y resoluciones.
  • Buscar referencias textuales y fechas en grandes volúmenes.
  • Organizar evidencias documentales y comprobantes.
  • Controlar acceso por usuario o grupo según política definida.
Confidencialidad: documentos jurídicos, identificaciones y expedientes pueden contener datos personales sensibles. El servidor debe tener cifrado, control de acceso, respaldos probados, registro de accesos, retención y procedimientos de eliminación. No exponer la interfaz a Internet sin una arquitectura segura y revisión profesional.

Paperless-ngx documenta una API REST. Desde una aplicación propia se pueden autenticar usuarios, consultar documentos, buscar texto, cargar archivos, consultar metadatos y gestionar objetos permitidos por los permisos del usuario.

Android como cliente

Aplicación nativa para cámara/escáner, captura de páginas, carga, consulta, búsqueda, vista previa y sincronización con el servidor.

Windows como cliente

Acceso web desde navegador, integración con carpetas de trabajo y utilidades de escritorio conectadas por API.

Arquitectura recomendada

Paperless-ngx permanece como servicio de servidor (Linux/Docker). Nuestra aplicación Android/Windows actúa como interfaz y cliente de API. No conviene intentar empaquetar todo el servidor dentro de un APK: base de datos, OCR, colas y almacenamiento requieren recursos y administración propios.

La API contempla token, sesión y otros métodos de autenticación; la aplicación debe proteger tokens, usar HTTPS y aplicar permisos en servidor. Nunca incluir credenciales maestras dentro del APK.

Digitalización por volumen

Cobro por página o lote: escaneo, limpieza, OCR, clasificación y entrega de archivo consultable.

Implantación

Instalación de servidor, configuración de usuarios, tipos documentales, etiquetas y flujos de captura.

Servicio administrado

Respaldo, actualizaciones, monitoreo, mantenimiento y soporte recurrente.

Solución por sector

Plantillas y flujos para traductores, despachos, inmobiliarias, talleres, gestorías y pequeñas empresas.

Migración de archivos

Importar carpetas históricas, normalizar nombres, deduplicar y crear índices de búsqueda.

Capacitación

Formación para personal administrativo sobre escaneo, clasificación, consulta y protección documental.

Cómo cobrar sin vender el software como propio

Ofrecer el proyecto de implantación, personalización, integración, alojamiento, capacitación y soporte. Si entregamos copias de Paperless-ngx o versiones modificadas, cumplir las obligaciones GPL-3.0, incluyendo licencia, avisos y código fuente correspondiente. La marca Paperless-ngx no debe presentarse como marca propia ni sugerir aval del proyecto.

La instalación oficial recomienda Docker y Docker Compose. La plataforma incluye varios servicios y necesita almacenamiento persistente, base de datos, OCR y una estrategia de respaldo. Para un despliegue estable, conviene un equipo Linux o VPS con recursos acordes al volumen y número de usuarios.

Elegir dónde alojar
Servidor Linux propio o VPS administrado. Para comenzar, un entorno de pruebas aislado, sin documentos confidenciales reales.
Preparar Docker Compose
Descargar los archivos Compose y variables desde el repositorio oficial, seleccionar el backend de base de datos recomendado y revisar volúmenes.
Definir almacenamiento
Separar directorios de consumo, datos y medios; configurar espacio, permisos y política de respaldos externos.
Configurar OCR
Elegir idioma(s) de reconocimiento; para documentos en español e inglés, instalar y probar los paquetes de idioma correspondientes.
Crear usuario y seguridad
Configurar superusuario, usuarios, grupos, permisos, HTTPS, firewall y acceso remoto seguro.
Probar restauración
Respaldar base de datos y documentos; restaurar en un entorno separado y comprobar integridad antes de uso productivo.
Integrar clientes
Usar API REST documentada; versionar la API y probar autenticación, permisos, carga y búsqueda.
Windows 7 no es una plataforma adecuada para alojar el servidor moderno de Paperless-ngx. Se recomienda Linux. Windows 10/11 puede servir como cliente y, con Docker/WSL2 y requisitos vigentes, como entorno de laboratorio; no convertirlo automáticamente en servidor productivo.

Paperless-ngx se distribuye bajo GNU GPL versión 3.0. Podemos cobrar por instalación, soporte, alojamiento, personalización y servicios; la GPL no prohíbe cobrar. Si distribuimos copias o una versión modificada, debemos cumplir los términos de la licencia, incluyendo entregar u ofrecer el código fuente correspondiente bajo las condiciones GPL.

El mero acceso remoto de usuarios a una instancia alojada no activa por sí solo una obligación AGPL: Paperless-ngx usa GPL, no AGPL. Aun así, si distribuimos contenedores, instaladores, copias modificadas o un paquete integrado, hay que revisar cómo se combinan los componentes y sus licencias.

Estrategia prudente: mantener Paperless-ngx como servicio independiente, conectarlo por API REST y mantener nuestra aplicación separada. Antes de distribuir un producto integrado, realizar revisión de cumplimiento GPL y dependencias.
03 · Diseño editorial / preprensa
ScribusPublicación con precisión.

Aplicación de autoedición (DTP) para maquetar documentos multipágina y preparar archivos de impresión. Es especialmente valiosa cuando se necesita control de tipografía, retícula, color y exportación PDF.

GPL-2.0-or-later

Diseño editorial con estructura profesional.

Scribus no pretende sustituir todas las herramientas de ilustración vectorial. Su fortaleza es organizar texto e imágenes en páginas, controlar el flujo editorial y generar archivos preparados para impresión o distribución digital.

DTP · CMYK · ICC · PDF

Maquetación multipágina

Páginas, guías, márgenes, columnas, marcos de texto e imagen, capas, estilos y páginas maestras.

Tipografía y texto

Control de fuentes, estilos de párrafo y carácter, ajuste de texto, alineación y composición.

Imágenes y gráficos

Marcos de imagen, escalado, recorte, vínculos a recursos y composición con elementos vectoriales.

Color profesional

Espacios CMYK, colores directos/spot y gestión de color ICC para flujos de impresión compatibles.

PDF y preprensa

Exportación PDF con opciones de impresión, fuentes, imágenes y configuración de salida según el proveedor.

Automatización

Funciones de scripting disponibles para automatizar ciertas tareas repetitivas y construir flujos editoriales.

El resultado depende de la configuración del documento, fuentes instaladas, perfiles ICC, imágenes enlazadas, versión de Scribus y requisitos de la imprenta. Siempre se debe revisar el PDF final y solicitar especificaciones de producción.

Catálogos

Productos, servicios, fichas técnicas, tarifas y catálogos comerciales multipágina.

Boletines

Boletines corporativos, revistas internas, informes y publicaciones periódicas.

Documentos corporativos

Manuales, memorias, propuestas, reportes, portafolios y dossiers.

Tarifarios

Listas de precios, menús, cartas de servicios y hojas de producto.

Promocionales

Folletos, trípticos, flyers, fichas y material de punto de venta.

PDF de imprenta

Archivos con configuración de color, sangrados y recursos revisados.

Una división de trabajo razonable es usar una herramienta vectorial para logotipos, ilustraciones, rotulación y piezas individuales; Scribus para integrar textos, fotografías, tablas, páginas maestras y documentos extensos. Los recursos se pueden intercambiar mediante formatos compatibles como PDF, SVG o imágenes, verificando que cada exportación conserve calidad y color.

Ventaja operativa: crear plantillas maestras de catálogo, propuesta, informe y boletín. Al estandarizar retículas, estilos, márgenes y componentes, cada nuevo proyecto requiere menos tiempo y conserva coherencia visual.

Paquetes de servicio

  • Catálogo básico: estructura, portada, estilos y PDF de distribución.
  • Catálogo de impresión: preprensa, perfiles, sangrado, revisión y entrega.
  • Actualización periódica: sustitución de precios, productos, fotografías y fichas.
  • Plantilla editable: archivo fuente, manual breve y recursos organizados.
Diseño por página

Cotizar por complejidad, cantidad de páginas, tratamiento de imágenes y tablas.

Paquetes de catálogo

Tarifas por rangos de páginas, variantes y entregables digitales o impresos.

Actualización mensual

Servicio recurrente para catálogos vivos, listas de precios y boletines.

Plantillas comerciales

Crear y vender plantillas sectoriales con estilos y páginas maestras.

Preprensa y revisión

Inspección de PDF, fuentes, resolución, sangrado, perfiles y salida.

Capacitación

Entrenamiento en maquetación y entrega de archivos fuente organizados.

La rentabilidad depende del alcance, número de revisiones, calidad de los originales, licencias tipográficas y especificaciones de impresión. Conviene presupuestar correcciones y cambios de contenido por separado.

Windows 7: la existencia de un instalador x64 de Scribus 1.6.7 no demuestra compatibilidad oficial con Windows 7. La versión actual debe probarse en el equipo real antes de adoptarla. Windows 10/11 son las opciones recomendables para versiones actuales.

Scribus es una aplicación de escritorio en C++/Qt. No hay que presentarlo como una aplicación Android oficial ni asumir que su interfaz de escritorio se puede compilar directamente como APK sin un trabajo importante de portabilidad y dependencias.

Opción recomendada: servidor

La app Android crea o edita un proyecto simplificado, envía datos y recursos a un servicio de composición en un equipo Linux/Windows compatible, y recibe PDF de salida.

Opción a largo plazo: app nativa

Desarrollar una interfaz táctil y motor editorial propios para Android. Reutilizar conceptos, formatos abiertos y componentes permitidos tras revisar la GPL y dependencias.

La primera opción permite validar el negocio sin reescribir el motor editorial. La segunda puede ofrecer más independencia y experiencia móvil, pero requiere inversión sustancial en diseño, tipografía, paginación, edición y exportación.

Scribus se publica bajo GPL-2.0-or-later. Se puede usar en trabajos comerciales y cobrar por los documentos producidos. Los PDF y diseños que creamos no se vuelven automáticamente GPL por haber sido creados con Scribus.

Si distribuimos Scribus o una versión derivada, hay que cumplir GPL: conservar avisos, entregar la licencia y proporcionar el código fuente correspondiente bajo sus términos. Si una aplicación propia se comunica con Scribus como proceso separado, la evaluación depende de la forma de comunicación, integración y distribución; no basta con llamarlo “módulo externo” para resolver jurídicamente todos los casos.

Recomendación: comenzar usando Scribus como aplicación independiente y motor de composición externo. Mantener nuestro código y datos en formatos interoperables; revisar dependencias y scripts antes de redistribuir paquetes.
Cierre · estrategia y decisión

Cómo aprovechar las tres sin mezclar sus responsabilidades.

Cada tecnología debe resolver una parte distinta del trabajo. La arquitectura más rentable no es necesariamente una aplicación monolítica: puede ser un conjunto de productos coordinados, con servicios compartidos y módulos independientes.

Fase 1 · Validación técnica
Instalar Scribus en Windows 10/11 y realizar un catálogo de prueba; desplegar Paperless-ngx en Linux con documentos ficticios; compilar un plugin DPF de ejemplo y probarlo en dos anfitriones.
Fase 2 · Prototipos vendibles
Crear una suite pequeña de plugins; una instalación Paperless configurada para una oficina; tres plantillas editoriales reutilizables.
Fase 3 · Pruebas con clientes
Medir tiempo ahorrado, errores, facilidad de uso, volumen, soporte requerido y disposición de pago antes de invertir en funciones adicionales.
Fase 4 · Producto y marca propios
Definir nombres comerciales, manuales, empaquetado, licencias, precios, sitio de soporte, política de actualización y matriz de compatibilidad.
Fase 5 · Expansión móvil
Primero Paperless por API REST en Android; después estudiar un cliente editorial y generación de PDF remota para Scribus. DPF/Android se evalúa por separado mediante AAP.

En cualquier producto distribuido conviene incluir un apartado “Créditos y licencias de terceros”, conservar textos de licencia y preparar un inventario de componentes (SBOM) con versiones y origen.

Más inmediato: Scribus

Puede ampliar servicios editoriales con inversión relativamente baja, si la versión funciona en el equipo y se domina preprensa.

Mayor ahorro operativo: Paperless

Producto digital escalable: DPF

Permite crear activos propios vendibles; requiere más ingeniería, pruebas de audio, soporte y compatibilidad.

Indicadores a medir

Horas por trabajo, costo de soporte, páginas procesadas, fallos, tasa de recompra, instalaciones activas y margen por cliente.

No se proyectan ingresos ni precios sin pruebas de mercado. Antes de fijar tarifas, calcular horas reales, costos de servidor, soporte, impuestos, medios de pago, distribución y mantenimiento.

Antes de instalar: descarga únicamente desde repositorios o sitios oficiales, verifica versión y arquitectura, conserva el instalador y su hash cuando esté publicado, registra las dependencias y prueba primero en un entorno aislado. No existe una versión Android oficial de Scribus equivalente al programa de escritorio.
